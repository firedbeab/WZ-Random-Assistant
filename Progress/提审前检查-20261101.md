## 一、阻断项：必须先处理

### 1.1 审核员打开可能是「满屏加载失败」（最高风险）

**现象**：审核员打开小程序后，首页、歌单、我的、反馈中心全部显示「读取失败」或「测试数据仅限超级管理员」。

**原理**：
- `utils/runtime.js:16-18` 把「测试模式」定义为 `envVersion !== 'release'`，即开发版和体验版都算测试模式
- 提交审核的版本对审核员而言是**体验版**（`trial`），因此 `isTestMode()` 恒为 `true`
- 前端调用云函数时自动带 `_testMode: true`（`pages/index/index.js` 经 `utils/runtime.js` 的 `cloudCall`）
- 云函数 `getUserInfo/index.js:25-30` 遇到测试域会调 `canUseTestData`，审核员既不是正式超管也不在白名单 → 返回 `TEST_ACCESS_DENIED`
- 首页收到该错误后抛 `SCHEDULE_READ_FAILED`，歌单区显示读取失败

**为什么 v1.8 能过而这次危险**：`canUseTestData` 闸门是 2026-10-23 提交（`fcf466d`），v1.8 发布（`0c9b5f1`）在 1 小时后。若当时云函数未同步部署该闸门，v1.8 审核时不会触发。本次云函数已按轮部署，闸门确定生效。

**必须验证（决定性）**：用一个**不在白名单、也不是超管**的普通微信号扫描体验版，依次打开首页 → 歌单 → 我的 → 反馈中心，看是否正常显示。

**修复方案（二选一）**：
- 方案 A（推荐）：`canUseTestData` 返回 false 时不报错，而是**降级使用正式数据域**。这样超管/白名单看测试数据，其他人（含审核员）看正式数据，两边都正常。
- 方案 B：`utils/runtime.js` 改为只有 `develop` 才进测试域，体验版走正式数据。改动小，但会失去「体验版用测试数据验收」的能力。

### 1.2 内容安全审查在生产大概率从未生效

**证据链（三条独立证据交叉验证）**：

1. `cloudfunctions/checkWeeklyCode/config.json` 的 `permissions.openapi` 是**空数组**
2. 该函数 `index.js:164` 调用了 `cloud.security.msgSecCheck`
3. 微信官方规则：云调用未在 `config.json` 声明接口权限时返回 `-604101` 错误
4. 该处 `catch` 的处理是 `console.warn` 后**继续放行**（`index.js:174-178`）

从云上下载的 `config.json` 与本地一致（空权限），说明不是本地与线上不同步。

**影响范围**（`backend-audit` 核查后确认）：
- `checkWeeklyCode`（投稿主链路）：内容检查失效 + 异常放行
- `adminAuditPlaylist:655`（管理员编辑投稿备注）：同上
- `drawWeeklyPlaylist:167` 与 `adminAuditPlaylist:140`：订阅消息 `subscribeMessage.send` 未声明 → 用户收不到发布通知
- `manageHelpContent`：**没有 config.json** 却调 msgSecCheck，且失败即阻断 → 管理员可能一直发布不了说明

**审核风险**：审核员若在投稿框提交违规文字并能成功，会判定「UGC 内容未做安全审核」直接驳回。

**修复**：为 4 个函数补 `config.json`：
```json
{ "permissions": { "openapi": ["security.msgSecCheck", "subscribeMessage.send"] } }
```
（`manageHelpContent` 只需 `security.msgSecCheck`）。重新上传后等待约 10 分钟缓存生效，再用一条违规样例实测确认返回 `suggest: risky`。

### 1.3 没有举报入口

微信对「用户能发布内容、其他用户能看到」的小程序硬性要求：必须有**内容审核机制 + 举报/投诉入口**。

现状：全项目搜索「举报 / 投诉 / 申诉 / report」= **0 处**。

唯一的「用户文字对他人可见」位置是**每周歌单里的曲名、歌手、备注**（`pages/playlist/index.wxml`）。

**修复建议**（任选其一）：
- 歌单页曲目长按菜单增加「举报此内容」
- 反馈中心增加「内容举报」分类，并在页面写明「发现不当内容可在此举报，24 小时内处理」

## 二、高风险项：可能被问询或驳回

### 2.1 发布说明备注无审核却直接给用户看
`adminAuditPlaylist/index.js:579` 把管理员输入的 `note` 原样写入 `admin_note`，全程无内容检查；该字段在用户端显示为「广播站说明」（`pages/playlist/index.wxml:64-66`）。这是唯一「无审核却直接展示」的文本。

建议：发布前对该字段执行与「编辑备注」相同的检查，失败则阻断发布。

### 2.2 隐私弹窗声明与实际收集不一致
`components/privacy-popup/privacy-popup.wxml:14-25` 声明收集三项：设备信息、剪切板、所选图片。

实际收集的是：微信 openid、歌名/歌手/备注、自定义称呼、反馈内容。而剪切板**只写不读**（`setClipboardData` 4 处、`getClipboardData` 0 处），设备信息只取尺寸做布局、不上传。

结论：**多声明了两项不收集的，漏声明了四项实际收集的。**

必须去微信公众平台后台核对《用户隐私保护指引》的勾选项，同时把弹窗文案改成与实际一致。

### 2.3 使用说明可能一直发布不了
`manageHelpContent` 调用 msgSecCheck 但缺 `config.json`，且其失败策略是**阻断**（`index.js:207/373/419`）。若线上同样缺声明，管理员每次发布说明都会看到「内容安全检查暂不可用」。
