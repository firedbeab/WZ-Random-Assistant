## 一、App 是否开源

### 结论：闭源

公开范围内只有两个官方仓库：

| 仓库 | 内容 | 说明 |
| --- | --- | --- |
| [KusStar/rewind-docs](https://github.com/KusStar/rewind-docs) | 官网源码（Nextra + Tailwind + Codrops TileScroll） | 不是客户端工程 |
| [KusStar/rewind-apks](https://github.com/KusStar/rewind-apks) | 编译后的 APK（v3.5.0，约 10.4MB） | 只有产物，无源码 |

包名 `com.kuss.rewind`，按 arm64 / armeabi-v7a / x86 / x86_64 分发。第三方评测（[异次元软件世界](https://www.iplaysoft.com/rewind.html)）明确写明"应用免费，但并无开源"。

检索范围包括 GitHub、Gitee、APKPure、APKCombo、AppBrain、逆向社区、应用商店，关键词含 `KusStar rewind`、`com.kuss.rewind jadx`、`倒带 音乐播放器 源码` 等，**均未找到客户端源码、反编译工程或技术拆解文章**。

> 因此本文档的设计结论来自：官网截图、官方操作指南、公开评测、APK 元数据、公开更新日志——不是读源码得来的。

## 三、换肤与自定义背景

### 3.1 已确认的交互流程

综合 [3h3 教程](https://www.3h3.com/az/224854.html)、[iPlaySoft 评测](https://www.iplaysoft.com/rewind.html)、[GHXI 页面](https://www.ghxi.com/daodai.html)：

```
左上角汉堡菜单
  → 换肤
    → 背景图 / 上传图片
      → 从本地选择图片
        → 裁剪
          → 右上角对勾确认
            → 应用为全局背景
```

可确认的选项：使用本地图片作背景、对图片裁剪、**调整背景透明度**、作为皮肤应用。侧边菜单还包含定时、语言等设置。

### 3.2 证据 vs 推断

**已确认**：
- 官方播放页使用全屏模糊化的专辑封面背景；
- 自定义皮肤流程包含图片选择与裁剪；
- 多篇介绍提到背景透明度可调；
- 需要读写外部存储权限以访问本地图片；
- 数据以本地保存为主。

**合理推断（无源码证明）**：
- 裁剪后的图片大概率复制/缓存到应用私有目录，避免原图移动后皮肤失效；
- "透明度"可能通过前景内容层、蒙层或 ImageView alpha 实现；
- 全屏播放页的模糊封面与自定义全局背景**可能是两套独立逻辑**，不能凭截图认定共用同一图像管线。

**未找到证据**（不要当成它的功能）：
- 自动分析图片明暗并切换黑白文字；
- WCAG 对比度计算；
- 自动生成渐变蒙层；
- 根据封面提取主题色；
- 自动模糊强度调节；
- 动态壁纸 / 视频背景；
- **多套具名预设主题**（公开描述只有"换肤""本地图片""透明度"）。

### 3.3 更新日志中的实现细节

官方 Telegram 更新记录（[Rewind News](https://t.me/s/Rewind_News)）：

- 3.2.0：播放内核由 `MediaPlayer` 重构为 `ExoPlayer`；
- 3.2.0：设置中加入「**禁用页面过渡动画**」——用户曾反馈动画数量多、速度偏慢；
- 侧边栏「功能 → 均衡器」可调用系统 EQ；
- 增加歌手/专辑页、关注歌手新歌页；
- 3.2.2：Android 11 适配；歌手页改为**不可滚动的 Tab 结构**。

## 四、官网源码中的设计参数

### 4.1 能核验的部分

仓库确认使用 Nextra、`nextra-theme-docs`、Tailwind CSS、Vercel、Codrops TileScroll。

`tailwind.config.js` 全文极简，只有两个按钮阴影：

```js
theme: { extend: { boxShadow: {
  'btn': '0 5px 10px rgba(0, 0, 0, 0.12)',
  'btn-hover': '0 30px 60px rgba(0, 0, 0, 0.12)',
}}},
darkMode: 'class',
```

`styles/base.css` 是 TileScroll 的原版样式：圆角 `8px`、边框 `2px solid`、过渡 `transform/background-image/box-shadow 0.2s ease-in-out`、图片墙旋转 `22.5deg`。

运行时实测（浏览器读取计算样式）：

| 项 | 值 |
| --- | --- |
| 背景色 | `rgb(17,17,17)` = `#111111` |
| 文字色 | `rgb(243,244,246)` = `#f3f4f6` |
| 字体栈 | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Noto Sans", ...` |
| 布局 | Nextra 文档骨架 + `.content{ padding:3rem; min-height:90vh }` |
| 响应式断点 | `53em`（约 848px）断点切换 4 列 grid 布局 |

### 4.2 未能核验的部分

官网组件的字号、行高、圆角、间距、按钮尺寸、过渡时长、缓动曲线**未能逐一核验**——codex 的只读沙箱无法读取外部克隆目录，raw 内容也未命中缓存。

> 重要边界：**即使拿到官网的精确 CSS，也只能证明官网的视觉实现，不能证明 Android App 使用相同的设计令牌。**

### 4.3 可以可靠提炼的设计规律

- 黑、白、中性灰为主，弱化平台品牌色；
- 高信息密度页面用简单纵向列表 + 大量留白；
- 低频功能放入侧边栏，主页面减少常驻按钮；
- 全屏播放模式隐藏常规控件，以手势承担播放与切歌；
- 专辑封面既是内容，也是主要视觉装饰；
- 自定义背景配透明度控制，不为个性化建立复杂主题系统；
- 页面动画允许关闭，照顾低性能设备与不喜欢强动效的用户。

## 五、对本项目的可迁移结论

| 结论 | 迁移方式 |
| --- | --- |
| 无边框、靠留白与色阶分层 | 本项目七条硬规则之一：微色阶分层，底色与卡片亮度差 ≥4% |
| 一个圆形符号贯穿全局 | 列表用圆形序号徽记，与彩蛋的圆形元素呼应 |
| 低频功能收进侧边/抽屉 | 「我的」入口统一收纳管理后台、图鉴、外观设置 |
| 个性化靠"任意图片 + 透明度" | 预设渐变 + 自定义背景（裁剪、压缩、遮罩、透明度滑块） |
| 动效要可关闭 | 只做三类轻动效，150–220ms，提供"减弱动效"开关 |
| 全屏沉浸只用于特定页面 | 仅彩蛋弹窗，首页不做沉浸式（机型适配成本高） |
| 不照搬黑底 | 浅色为主，深色跟随系统 |

**明确不迁移**：
- 全屏模糊封面（本项目无封面图，且 `filter: blur()` 低端机掉帧）；
- 复杂手势（与小程序页面滚动、返回手势冲突）；
- 多平台账号体系（本项目场景不同）。
