# 管理后台 I 版 · 功能对照与落地边界

> 2026-10-27，美国东部时间。对照正式 pages/admin 的 WXML/JavaScript，参照 H 版第二稿；I 版尚待用户评审。
>
> 样稿：[I-admin-workbench.html](mockups/I-admin-workbench.html)。正式页面、云函数、权限与业务数据均未修改。HTML 的角色和环境选择器只用于看样稿，不是真实身份切换。

## 这版调整什么

- 保留 H 版已讨论的「管理后台」固定页头、管理员两项/超管四项主导航、草稿验证码明文、普通管理员均可撤销、说明十图等方向。
- 曲目正常时歌名与歌手同行，字号与颜色有主次；长文本完整换行。审核默认用序号，进入某一天的选择模式后才显示勾选。
- 只在同一天内批量标记移除，不把既有单日操作改成跨日批量请求。底部根据当前任务显示发布或单日移除操作。
- 详情隐藏一级页签，保留管理后台页头、明确返回与17px详情标题；信息区在只读和编辑间切换，避免重复填写。
- 「控制台」仍是主导航，展示运行/测试工具；管理中的「数据与通道」承接记录维护，避免两个控制台名称难以分辨。控制台保留通道管理的跳转入口。
- 数据统计用一块主摘要替代四张等重小卡，标明本周与全部用户的不同口径；通道当前状态常显，调整放在单独确认中。

## 审核与发布

| 正式功能 / 方法 | I 版位置 | 样稿表现与落地要求 |
| --- | --- | --- |
| 云端恢复角色、无权限返回；checkPermissionFromCloud | 管理后台入口 | 仅展示角色差异；真实云端校验必须保留，不能用隐藏页签替代 |
| onBackHome | 原生导航返回 | 顶层提示返回首页；样稿没有正式首页，不跳到真实项目 |
| onPullDownRefresh、loadPlaylist | 审核刷新、无数据/失败状态 | 保留刷新路径；样稿不请求云端 |
| 审核通知订阅、查询状态 | 页头铃铛 | 仅改变本页模拟状态；真实一次性订阅及消费规则不变 |
| 审核须知四项 | 审核要点弹层 | 可打开、关闭，不常驻占据首屏 |
| 排期周次、非当前周提醒 | 页头播出范围、旧周期提示 | 显示日期不改变 week_key 的北京时间计算；可切“非当前周排期”示例 |
| 历史候补整期提示 | 正式待接入状态提示槽 | 样稿没有再造候补数据；真实 carryover_only 提示不得省略 |
| 五天排期、有效/待删除数量 | 同一内容面内按日分组 | 数量由示例状态计算；真实 dayCounts 保留 |
| 长按复制完整歌名/歌手/备注 | 曲目文字区 | 长按或右键复制示例完整内容；正式隐私授权和失败提示保留 |
| 添加/编辑/删除特殊备注 | 曲目「更多」→特殊备注 | 保存、删除确认与50字限制已演示；复用原保存、内容安全与刷新流程 |
| 异常原因选择、其他原因、尝试替补 | 曲目「更多」→异常并替补 | 显示原因与示例替补结果；真实候补不足、失败与错误提示仍走原接口 |
| onAuditSelectionChange / onRemoveSelectedFromDay | 每日「选择」→底部单日移除条 | 保留日索引、可选原因、不补位；不能生成新的跨日移除API |
| onRestoreRemoval | 待移除曲目右侧「撤销」 | 可恢复本页标记；真实撤销请求、版本校验不变 |
| onSkipDay | 每日「跳过」→确认 | 直接清空当天示例、说明转回候补；不提供一键撤销，不与待移除混用 |
| 当周公开备注、onNoteInput | 发布说明折叠区、发布摘要 | 共用同一份示例备注，100字；正式字段与提交参数不变 |
| onPublish、待移除最终生效、空排期备注必填 | 底部发布歌单→发布摘要→确认 | 空歌单未填说明时禁用确认；仅演示本页发布，不发通知、不落库 |
| 写入中的禁用、失败提示、旧revision刷新 | 正式请求层 | HTML不冒充真实异步请求；实际迁移必须原样保留 |

注意：审核“标记移除”与整天“跳过”的后果不同。现有 skipDay 清空该日并将对应投稿转为候补；它不是可随时撤销的待删除标记。

## 落地时的验收门槛

本轮验证仅覆盖 HTML 代表性交互与现有回归：23个测试文件共64项通过，正式源文件和 H 样稿无差异；运行时源文件预算仍为356.2KiB。截图见设计方案10.13。正式接口写入、权限及真机并未因样稿验证而完成验收。

1. 本轮只评审HTML，不能把页面点击成功当作真实后端回归。
2. 迁移只改展示和交互组织。请求名、参数、日索引、revision、时间口径、角色恢复、数据域和服务端闸门逐项对照，不顺手重构业务。
3. 新入口与原方法建立映射；需拆分页时先讨论。isTestEnv 与 isSuperAdmin 现有判定不能被样稿“2/4个页签”替换。
4. 真实写入保留防重复、忙碌状态、二次确认、失败反馈、过期后刷新；新增确认样式不能削弱服务端预览令牌与限制。
5. 验收至少覆盖普通管理员/超管、测试/正式、旧排期、零曲目、无排期、失败、长文本、320px、浅深色与返回未保存内容。
6. 确认后才改正式页面，按原64项测试加受影响业务回归与普通账号真机验证；不在这轮上传前端或部署云函数。
