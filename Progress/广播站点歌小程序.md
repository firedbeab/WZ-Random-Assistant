## 三、当前核心业务规则

> 本节为当前有效规则；开放窗口扩展已于2026-11-01部署，前端控制台和展示增强仍需随新版小程序发布。

### 3.1 每周流程

```text
周五 02:00       自动生成并发布本周验证码
周五 20:00       提交通道开放
周五20:00至周日20:00 用户提交内容（48小时）
周日 20:00       自动抽取，生成待审核排期
管理员审核        标记异常、自动替补、跳过日期、编辑备注
管理员发布        排期变为 published，向已订阅用户发送通知
周一至周五        用户查看本周排期
```

所有业务日期按北京时间 UTC+8 计算。`week_key` 使用相关周日的 `YYYY-MM-DD`；周五至周日归属同一期。用户端显示随后周一的YYYY.MM.DD期，仅展示转换，不改原键。

### 3.2 通道状态

默认开放条件：北京时间周五20:00（含）至周日20:00（不含）。

| 模式 | `forceOpen` | `forceClose` | 结果 |
| --- | --- | --- | --- |
| 正常 | false | false | 按时间窗口判断 |
| 强制开放 | true | false | 跳过时间限制 |
| 强制关闭 | false | true | 始终拒绝提交 |

优先级：强制关闭 > 强制开放 > 默认时间窗口。前端只负责展示，`checkWeeklyCode` 会在服务端再次校验。

### 3.3 当前提交链路

```text
参数类型与长度校验
→ 服务端时间窗口和通道状态校验
→ 微信文本内容安全检测
→ 开启数据库事务
→ 验证已发布验证码及到期日期
→ 检查 user_id + week_key，限制每人每周一次
→ 按规范化 song_key 检查本周同名内容
→ 统计本周 pending 数量
→ 未满250条：完整写入 pending
→ 已满250条：完整写入 overflow，仍返回成功并增加计数
```

`overflow` 保存内容名称、歌手和特殊备注，使用户刷新或更换设备后仍能看到自己的提交；它不参与抽取或异常替补，按所属期次保留六个月；发布不再立即清理。

### 3.4 当前名称判重规则

`song_key` 由内容名称计算：

- 使用 Unicode NFKC 统一全角和半角。
- 英文统一为小写。
- 忽略空白、标点和符号。
- 歌手、补充说明和特殊备注不参与唯一性判断。
- 旧数据没有 `song_key` 时按 `song_name` 即时计算。

| 输入 A | 输入 B | 当前判定 |
| --- | --- | --- |
| `夜曲` | `夜 曲` | 相同 |
| `Hello!` | `ＨＥＬＬＯ` | 相同 |
| `《夜曲》` | `🎵夜曲` | 相同 |
| `晴天` | `晴天（Live版）` | 不同 |

边界：错别字、别名、拼音或额外文字仍可能绕过；过度模糊匹配会误伤真正不同内容，当前不启用。

### 3.5 当前抽取规则

1. 分页读取本周所有 `pending`，以及前两周所有 `carryover`。
2. 当前用户本周已有任意提交时，不再使用该用户的历史候补，避免同一用户一周占两个位置。
3. 按规范化 `song_key` 去重；同名多人提交时随机保留一条，避免始终偏向早提交者。
4. 从前两周已发布 `schedules` 建立重复集合。
5. 候选优先级为：本周新内容 → 历史新内容 → 本周重复内容 → 历史重复内容。
6. 依次填入 `day1` 至 `day5`，每天最多 4 项，共 20 项；所有候选不足时保留空位。
7. 事务写入一条 `revision=1` 的待审核排期，并把被选提交改为 `selected`；排期项目保留 `source_week_key`。

### 3.6 审核与发布

- `markException`：移除单项、记录异常、原提交改为 `rejected`；优先从本周 `pending` 替补，不足时使用前两周 `carryover`。
- `skipDay`：清空指定日期，相关提交改为 `rejected`，写入异常记录。
- `updateNote`：更新或删除特殊备注；空备注在最终列表不渲染节点。
- `publish`：事务内把排期从 `pending` 改为 `published`；随后把本周剩余 `pending` 改为 `carryover`，保留 `overflow` 供本人历史查询并发送用户通知。
- 清理和通知互相隔离；任一失败不撤销已经成功的发布。

### 3.7 当前数据保留

每次 `drawWeeklyPlaylist` 运行前清理：已发布 `schedules` 按 `week_key` 北京时间零点起保留六个自然月（月末钳制），未发布排期仍保留当前周和前两周；`submissions`（含overflow）按原期次保留六个月，发布时不再删除overflow；已消费且超过两周的订阅记录仍按原规则清理。`song_likes.expires_at` 跟随所属歌单，到期读接口立即隐藏、周任务再物理清理，重新点赞或重新发布不续期。历史判重仍只查前两期，候补仍只查前两周。之前已被删除的历史无法恢复。

### 3.8 本地缓存

| 缓存 | 用途 | 当前刷新策略 |
| --- | --- | --- |
| `prod_last_submission` / `test_last_submission` | 当前设备快速显示本周提交曲目 | 按运行环境隔离；进入和下拉刷新会用云端本人投稿校准，`overflow` 不因刷新丢失 |
| `prod_schedule_cache_{week_key}` / `test_schedule_cache_{week_key}` | 已发布列表 | 按运行环境隔离；所有缓存命中均先渲染，再后台静默校验云端，撤回后会清除旧缓存 |
| 使用说明缓存 | 网络异常时显示最近成功内容 | 下拉刷新强制请求 |
| 说明大图缓存 | 避免重复下载大图 | 约 12MB，按最久未查看淘汰 |
| 彩蛋清单和图片缓存 | 提前准备随机猫咪照片 | test/prod隔离；首页/开窗刷新清单，离线清单最多24小时，文件12MB LRU，取图等待2.5秒后回退文字猫 |
| `admin_auth` | 旧版兼容标记 | 实际角色始终由云端 `users.role` 决定 |

### 5.5 动态使用说明

- 用户端只显示已发布条目，按顺序折叠展示。
- 条目首次展开时创建正文和图片节点，后续折叠仅隐藏。
- 正文与标题用短横线区分，条目之间用整行细线；正文不另加色块。展开/收起采用高度与透明度过渡，旧WebView无法插值高度时仍须可展开、可读和可点击。
- 图片点击后下载到本地用户目录并进入约 12MB 的缓存。
- 每条说明最多 10 张图，管理端和 `manageHelpContent` 同步校验；单张云端限制仍为 2MB，客户端按需逐级压缩。为兼容旧选择器每批至多选择 9 张，可继续添加至 10 张；选择中禁止重复打开和保存，取消后解除状态。云端扩容已部署，新管理端尚未发布；1.8 的图片选择仍限五张。
- 用户端只创建前 4 张缩略图并准备其地址；超过时第四张显示“还有 N 张”，提示完整总数。点开仍向 `wx.previewImage` 传递完整有序图片列表，可以左右滑动查看后续图片；管理员编辑区保留全部图片的排序/删除，用户端预览同样只展示前四张。
- 图片客户端直传云存储，保存时由 `manageHelpContent` 下载复核大小和 JPG/PNG/WebP 文件头。
- 发布文本必须通过微信 `msgSecCheck`；草稿可以保存但不能绕过发布检查。

### 5.6 猫咪彩蛋

- 正式规则：随机5–20次入口；前五次至少一次二连；8次二连/2次三连/四连任一通关；随机50–96次保底后四次同点。关闭重开保留未完成轮次和保底，中奖后完成/放弃奖励才重置。
- 当前连续数字断连即替换；小点只在亮起时显示，混合计数取较高值。二连/三连喵动画固定在骰子区域四角、连续出现错位；通关彩带、随机邀请、十二种动画文字猫与照片淡入。
- 正式照片只来自启用云端条目；管理文案留空使用默认值。累计通关20%文字猫，四连优先照片，取图超时/无图/图片错误均回退文字猫。
- 两类奖励分别显示本机遇见数量，以当前启用图片条目和十二种文字猫为分母；预加载不计数，照片成功显示/文字奖励渲染后才记录，手动文字猫预览不计数。加权防重复保留所有条目的再次抽中机会（未遇见3、已遇见1、上一项0.5）。
- 测试面板使用原生scroll-view和固定关闭按钮；展开时上滑滚动不投掷，收起后恢复上滑投掷。
- 测试默认5次入口、10次内四连；超管展开“测试场景”逐项体验。缓存演示只读取实际云照片缓存，慢加载固定延迟1.6秒；这些演示不改变网络设置或正式云数据。
- 最近投稿回复：开窗后台调用 `getUserInfo.getLatestSubmission`（最多等待1.5秒，不阻塞奖励），只使用当前保留数据中的本人最新记录，不跨越最新不合格记录追溯。歌名/歌手各自满足1–5汉字才进入6句/8句固定模板池；外层《》只对歌名规范化，其他标点、数字、英文、内部空格或多歌手符号不处理，直接不合格。

对固定的一次最新投稿，且下方文案不是照片自定义时：

| 名称资格 | 个性化句数 | 连同普通文案的下方文字种类 |
| --- | --- | --- |
| 歌名和歌手均合格 | 14 | 15 |
| 仅歌手合格 | 8 | 9 |
| 仅歌名合格 | 6 | 7 |
| 均不合格/无记录/失败/读取未赶上奖励 | 0 | 1 |

- 设本次启用照片中默认下方文案有D张、自定义下方文案有C张，单类奖励下方文字可选数为K（上表15/9/7/1），最终奖励可见组合为 `K × (12 + D) + C`；再把先前4种邀请一起计入，为 `4 × [K × (12 + D) + C]`。图片不能加载时对应照片组合不可见，仅剩文字猫。
- 当前测试照片D=1、C=0：两项均合格时 `15 × 13 = 195` 种最终展示，包含邀请为780种；仅歌手时117/468种，仅歌名时91/364种，均不合格时13/52种。当前测试账号实际没有保留投稿，所以正常模式实际是后者；测试示例模式可逐句覆盖14个模板。
- 当前正式照片为0：两项均合格且查询及时成功时可展示 `15 × 12 = 180` 种文字猫组合，含邀请720种；无合格投稿则12/48种。正式添加启用照片后按上式重新计算。款式选择采用本机遇见权重，不能直接按组合数推算每款概率。

## 八、安全、隐私与性能

### 8.1 管理员安全

- `users.role` 是唯一可信身份来源；本地缓存不能授予权限。
- 超级管理员 bcrypt 哈希只存在 `verifyAdmin` 云函数环境变量 `SUPER_ADMIN_HASH`，不进入源码和 Git 历史。
- 普通管理员通行码使用 bcrypt 哈希，明文仅在创建时返回一次。
- 登录连续失败 5 次锁定 15 分钟。
- 管理云函数校验角色、输入类型、长度、文档 ID 和索引范围。
- 返回客户端的错误信息脱敏；详细异常只写云函数日志。

### 8.2 投稿安全

- 时间窗口、验证码、每周次数和通道状态均由服务端校验。
- 标题、补充说明和特殊备注有服务端类型与长度限制。
- 普通提交调用微信文本内容安全接口；明确违规会拒绝。
- `(user_id, week_key)` 唯一索引作为并发兜底。
- 2026-10-04 起歌手不参与内容唯一性，防止修改歌手绕过。

### 8.3 隐私

- 不主动获取微信昵称、头像、手机号或通讯录。
- 使用 openid 识别用户和管理员，但前端只在业务必要范围内使用。
- 测试审计不返回具体 openid。
- 使用说明图片只读取超级管理员主动选择的照片，不读取未选择内容。
- 本地隐私弹窗已按用户标识、主动填写内容、复制／订阅／管理员选图和屏幕布局说明；不读取剪贴板，不主动读取微信昵称。公众平台现网／提审指引仍须对照实际填写，本轮没有修改或宣称验收该外部协议。
- 仓库不包含用户数据、管理员明文通行码、超管哈希、私钥或真实本地项目配置。

### 8.4 内容安全

- 普通用户提交：`msgSecCheck` 检查标题、歌手/补充说明和特殊备注；明确违规拒绝提交，接口异常、复核或缺失结果均阻断（见 1.4 第 4 条）。
- 管理员备注：保存非空内容前执行 `msgSecCheck`；只接受明确通过，接口异常、复核或缺失结果均拒绝。
- 使用反馈：自定义称呼、反馈正文、超管回复、投票标题/说明/选项保存前都检查；接口不可用或未通过均直接拒绝，不放行。
- 使用说明与更新日志：草稿可保存但不绕过检查；发布标题、摘要和正文必须通过 `msgSecCheck`，检查不可用时拒绝发布。
- 彩蛋文案：超管保存非空文案前检查，未通过或接口异常都拒绝保存。
- 超管控制台的投稿编辑与排期编辑：检索文字后执行 `msgSecCheck`；只接受明确通过，接口异常、复核或缺失结果均拒绝。
- 发布歌单的广播站说明：非空说明在发布事务之前检查，失败不发布、不修改投稿状态。
- 云函数权限：投稿／说明／审核声明 security.msgSecCheck；审核／抽取声明 subscribeMessage.send，配置上传还需同步微信侧权限元数据并等待缓存。
- 图片类内容：超管入口、数量/大小限制、文件签名验证和管理员人工把关；当前未增加异步图片内容审核。

### 8.5 性能现状

- 首页用户信息与通道配置并行读取；提交状态和计数并行加载。
- 管理后台按页签加载，避免首屏请求全部管理数据。
- 抽取分页读取候选，候选和历史排期并行读取。
- 清理使用 `Promise.allSettled`，单项失败不阻断主流程。
- 已发布列表和使用说明使用本地缓存；大图采用按需下载和本地淘汰缓存。
- 已启用按需注入；当前页面声明的 `privacy-popup` 均实际使用。
- We分析中的同步 Storage 建议只有约 2-3ms 收益，属于低优先级，不为此单独发布。

## 九、部署与运维

### 9.1 环境规则

- 小程序仍连接同一个 CloudBase 环境，但运行时自动选择逻辑数据域：开发版/体验版走 `test_`，正式发布版走原集合。
- 环境判断只依赖微信提供的 `envVersion`：无法读取时按测试模式处理，采用“失败时不写正式数据”的保守策略。

#### 决策文档的收录标准（2026-10-27 定，任何 AI 接手前先读）

**一句话标准：只写“以后都这么做”的结论，不写“这一轮做了什么”。**

判断方法——把这句话读一遍，问自己它描述的是**规则**还是**过程**：

| 算决策（写进决策文档） | 不算决策（写进 `历史-更新记录.md`） |
| --- | --- |
| “测试域准入采用 openid 白名单”（以后都这么放行） | “今天把白名单从 1 人扩到 2 人并验证通过”（某轮动作） |
| “先讨论与 HTML 样稿，再改正式界面”（流程规矩） | “用户确认了 F.2 方案，已接入歌单页”（某轮结果） |
| “开发资料不进前端包”（打包策略） | “本轮主包从 1.8MB 瘦到 1.5MB”（某次数字） |
| “首页低频功能统一收纳”（长期方向） | “当前代码仍是两个入口，收纳页待开发”（当前进度） |

补充规则：

1. **一条里既有决策又有进展时，拆开处理**：决策部分留在决策文档，进展部分搬到历史更新记录，两边都不删内容。
2. **待选方案不算决策**。“F 版待评审”“双入口讨论中”这类没定论的内容，写进主文档待办或设计文档，不要占用决策编号。
3. **编号连续**：整理时若删除条目，后续条目顺次前移补上跳号，并在分区开头写明原编号去向。
4. **决策被推翻时**，不要删除旧条目——补一句“已于某日被某条取代”，保留追溯链。


### 11.8 本机环境与命令行约定

> 目的：换任何 AI 接手时不必重新踩一遍环境坑。以下都是 2026-10 实测结论。

- **命令行环境（2026-10-25 实测，重启后已生效）**：自动化工具进程现在跑的是 **PowerShell 7.6.8（Core）**，路径 `C:\Program Files\WindowsApps\Microsoft.PowerShell_7.6.8.0_x64__8wekyb3d8bbwe\pwsh.exe`；系统自带的 5.1 仍然并存、系统后台任务与其它软件继续用它，互不影响。不想要 7 时 `winget uninstall Microsoft.PowerShell` 可干净卸载。
  - 确认当前跑哪个版本：看 `$PSVersionTable.PSVersion`（7.x）或直接看进程路径。
- **不要换成 bash/WSL**：自动化入口固定为 PowerShell，外面再套一层只会多一层转义；Git Bash 虽存在（`C:\Program Files\Git\bin\bash.exe`）但无必要，WSL 未安装发行版。
- **默认输出编码已是 UTF-8**（PS7 带来的改善），中文可以直接输出，不必每次设 `[Console]::OutputEncoding]`；若某台机器退回 5.1 才需要手动设。
- **读写文件仍建议显式编码**：读取用 `Get-Content -Encoding UTF8`；写入用 `[System.IO.File]::WriteAllText($path,$text,(New-Object System.Text.UTF8Encoding($false)))`。带 BOM 的 JSON 会让命令行工具解析失败。
- **调用 `.cmd` 包装器时仍然不要内嵌双引号**（PS7 也治不好）：Windows 命令行会吞掉双引号。2026-10-25 复测：不含双引号的 `--fn-source` 能正常传入，含 `""` 的就报 `Unexpected token '{'`。需要传含引号的 JSON 时，写成 node 脚本用 `spawnSync` 调用。
- **PS7 已补上** `[System.IO.Path]::GetRelativePath` 与 `ConvertTo-Json -AsArray`（5.1 没有这些）；但单元素数组手动包 `[]` 的写法仍然通用，不必改。
- **本机没有 npm / pnpm / curl / jq / sqlite3**。Node 只在 DSH 运行时里：
  `C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`
  同目录下 pnpm 用 `pnpm\bin\pnpm.cjs`（通过 node 调用）。
- **执行策略仍禁止运行 `.ps1`**：要跑脚本就用 `.cmd` 包装，或直接用 node 跑 `.js`。
- 复杂操作（读云库、批量改数据、跑测试、生成二维码）优先写成一次性 node 脚本再调用，不要堆长单行 PowerShell。
