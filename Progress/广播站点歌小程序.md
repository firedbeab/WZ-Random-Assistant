## 一、项目概述

**项目名称：** WZ随机助手<br>**平台：** 微信小程序<br>**定位：** 通用内容提交与排期管理工具。用户每周日在限定时间窗口内提交内容请求，系统自动抽取并生成周一至周五的排期列表，管理员审核后发布。

**核心功能闭环：**

```text
用户提交内容 → 周日晚自动抽取 → 管理员审核 → 发布排期 → 用户查看
```

## 六、云函数详解

### 6.1 getUserInfo

**触发时机：** 每个页面 `onLoad` 时调用

| 逻辑   | 说明                                                                                           |
| ---- | -------------------------------------------------------------------------------------------- |
| 查询用户 | 根据 `OPENID` 查 `users` 集合                                                                     |
| 自动创建 | 不存在则创建 `{ openid, role: 'user', points: 0 }`                                                 |
| 并发保护 | `.add()` 遇到 duplicate 错误时重新查询返回已有文档                                                          |
| 通道状态 | 读取 `configs` 集合 `channel_override` 文档，返回 `channelForceOpen` 和 `channelForceClose` 字段（三态通道控制） |

### 6.2 checkWeeklyCode

**触发时机：** 用户点击"提交"按钮

```text
参数校验 → 通道开关检查（configs.channel_override：forceClose 优先拒绝 → forceOpen 跳过时间校验 → 默认周日8-20点）
→ 微信文本安全检测（msgSecCheck，scene: 2 评论场景，合并检查 title+remark+special_note）
  → 返回 risky 则拒绝，接口异常不阻断
→ 事务开始
  → 验证码有效性（weekly_codes 集合）
  → 验证码过期检查
  → 用户重复提交检查（submissions 按 user_id + week_key）
  → 250条上限检查
  → 写入 submissions（含 special_note 字段）
→ 事务提交（duplicate key 错误 → 返回"你本周已经提交过了"）
→ 递增 submission_counters（无论是否写入成功）
→ 返回 totalSubmissions
```

**关键设计：** 250条满额后仍返回 `success: true`，用户无感知。

**安全特性：** 事务 + 唯一索引双重保障防重复提交；`msgSecCheck` 接口调用失败时不阻断用户正常提交。

### 6.3 drawWeeklyPlaylist

**触发时机：** 每周日 20:00 由云开发定时任务触发（也可通过测试台手动触发）

```text
0. 清理过期排期（只保留本周 + 前2周）
1. 分页读取本周所有 pending 的 submissions
2. 去重（相同内容只保留一条，随机选择记录）
3. 黑名单过滤（前2周已排期的项目不再入选）
4. Fisher-Yates 洗牌（crypto.randomInt 密码学安全随机数）
5. 分配到 day1-day5（每天4项，共20项）
6. 仅提取审核/展示所需字段后，事务写入 schedules（竞态检查：防止重复抽取）
7. 更新被选中请求 status → 'selected'
8. 通知所有已订阅管理员（openid 去重 + 身份校验）
```

**管理员通知：** 抽取成功后调用 `notifyAdmins()`，查找所有 `type: 'admin'` 且 `consumed: false` 的订阅记录，逐个发送订阅消息。发送前校验用户是否仍是管理员（防止撤销后仍收到通知），同一 openid 只发一次。

**周标识计算（week\_key）：** 所有云函数统一基于北京时间（UTC+8），以本周日的日期 `YYYY-MM-DD` 作为唯一标识。

```js
// 北京时间 = UTC时间戳 + 8小时
const bjTime = new Date(now.getTime() + 8 * 60 * 60 * 1000);
// 本周日 = 当前日期 + (7 - 星期几) % 7
const diff = (7 - bjTime.getUTCDay()) % 7;
```

### 6.4 adminAuditPlaylist

**四种操作（action 参数）：**

| action          | 功能                                                                                    |
| --------------- | ------------------------------------------------------------------------------------- |
| `getPending`    | 获取本周 status='pending' 的排期（最多一条）                                                       |
| `markException` | 标记某项异常，原提交改为 rejected，并从剩余池中自动替补；无替补则直接移除                                             |
| `skipDay`       | 跳过某天（清空该日所有项目），原提交改为 rejected，并记录到 `schedule_exceptions`                              |
| `publish`       | 发布排期（事务内：检查 status='pending' → 更新为 'published'），同时将本周所有剩余 pending 请求标记为 rejected（软删除） |
| `updateNote`    | 更新单个项目的特殊备注（含 msgSecCheck 安全审核）                                                       |

**发布安全特性：** publish 操作使用事务包裹，先检查排期状态是否仍为 `pending`，防止多个管理员同时发布导致重复操作。发布成功后通知所有已订阅用户（`notifyStudents()`），按 openid 去重。

### 6.5 verifyAdmin

**身份验证流程：**

```text
输入通行码
  → 暴力破解检查（login_attempts 集合，5次失败锁定15分钟）
  ├── bcrypt 比对超管哈希（SUPER_ADMIN_HASH）→ 分配 superadmin 角色
  └── 遍历 admin_passcodes 集合，bcrypt 比对 → 分配 admin 角色
      → 将通行码 label 写入 users.admin_label（用于标识管理员身份）
→ 创建/更新 users 文档（写入 role）
→ 重置失败计数
→ 返回 { success, role }
```

**暴力破解防护：** 使用 `_.inc(1)` 原子递增记录失败次数，达到 5 次后锁定 15 分钟。并发创建 duplicate 时自动重试，确保不遗漏任何失败记录。

### 6.6 autoGenerateWeeklyCode

**触发时机：** 每周五凌晨 2:00 由云开发定时任务触发

| 逻辑   | 说明                           |
| ---- | ---------------------------- |
| 检查已有 | 本周已有验证码则跳过                   |
| 生成   | 3个6位大写字母+数字随机码               |
| 过期时间 | 周日 24:00 北京时间（= 周一 0:00 UTC） |
| 直接发布 | `is_published: true`         |

### 6.7 manageWeeklyCode

**五种操作：** `list` / `add` / `update` / `publish` / `delete`

- 已发布的验证码不可修改、不可删除

- `list` 时自动清理已过期的验证码

### 6.9 manageAdmins（仅超管可用）

| action           | 功能                                              |
| ---------------- | ----------------------------------------------- |
| `listPasscodes`  | 列出所有管理员通行码（标签 + 脱敏预览 + 创建日期）                    |
| `addPasscode`    | 生成 6 位通行码，bcrypt 哈希存储，明文仅返回一次                   |

### 6.10 manageHelpContent

**公开读取：** `listPublished` 只返回已发布条目的标题、摘要、正文、图片和排序字段，不返回操作人或内部时间字段。

**超级管理员操作：** `listAll` / `getForAdmin` / `initializeDefaults` / `uploadImage` / `deleteFiles` / `save` / `setPublished` / `reorder` / `delete`。每次写操作都会在服务端根据 `OPENID` 重新确认 `users.role === 'superadmin'`，不能只依赖前端入口隐藏。

**图片安全与资源控制：** 每条最多 5 张、单张最多 2MB；服务端按文件头确认只接受 JPG、PNG、WebP，以随机文件名写入 `help/` 云存储目录。替换或删除条目时同步清理不再使用的说明图片。用户端只在条目展开后加载图片，点击后调用微信原生全屏预览。

**展示约定：** 用户端和说明管理列表均不显示更新时间。管理端保留草稿、发布/隐藏和上下排序能力；完整编辑页提供用户端预览及未保存离开提醒。

## 七、数据库设计

### 7.1 集合清单

| 集合名                     | 用途     | 关键字段                                                                                                                             |
| ----------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `users`                 | 用户信息   | `openid`, `role` (user/admin/superadmin), `admin_label`, `channelForceOpen`, `points`, `created_at`                              |

## 八、核心设计思路

### 8.1 时间系统：全局北京时间

所有时间计算统一使用北京时间（UTC+8），不依赖服务器本地时区：

```js
const bjTime = new Date(now.getTime() + 8 * 60 * 60 * 1000);
bjTime.getUTCDay();    // 北京时间的星期几
bjTime.getUTCHours();  // 北京时间的小时
```

`week_key` 统一以本周日日期（YYYY-MM-DD）标识一周，所有云函数和前端保持一致。

### 8.2 防重提交：三层检测

```text
前端缓存层：last_submission (wx.Storage) → 命中则直接显示锁定状态
云函数层1：submissions 按 user_id + week_key 查询 → 重复则拒绝
云函数层2：submissions 按 week_key count → ≥250 则不写入（但返回成功）
```

### 8.3 250条上限：无感知

用户侧完全不暴露 250 条上限的存在：

- 满额后仍返回 `success: true` + "提交成功"

- 底部状态统一显示"已提交，请等待抽取"

- `submission_counters` 照常递增计数

### 8.4 历史排期：2周保留 + 自动清理

```text
保留范围：当前周 + 前1周 + 前2周（共3周数据）
清理时机：每次 drawWeeklyPlaylist 执行前
清理方式：删除 week_key 不在保留范围的 schedules 记录
黑名单：抽取时排除前2周已排期的项目，避免连续重复
```

### 8.5 抽取算法

```text
1. 读取本周所有 pending 的 submissions（分页，突破100条限制）
2. 按 song_name+singer 去重（相同内容只保留一条）
3. 排除黑名单（前2周 schedules 中出现过的项目）
4. Fisher-Yates 洗牌（均匀随机）
5. 依次填入 day1~day5，每天4项
6. 候选不足20项时保留实际抽取数量，不复制或重复填充
```

### 8.6 本地缓存策略

| 缓存键                         | 用途        | 刷新规则                                    |
| --------------------------- | --------- | --------------------------------------- |
| `last_submission`           | 用户本周提交信息  | 提交成功时写入，跨周自动失效（week\_key 不匹配）；下拉刷新时清除   |
| `schedule_cache_{week_key}` | 排期数据      | 切换标签时读取；历史周命中后不再刷新；最新周后台静默刷新；下拉刷新强制跳过缓存 |
| `admin_auth`                | 管理员登录兼容标记 | 由云端 `users.role` 自动恢复；路由和管理权限均以服务端角色为准  |

**下拉刷新同步：** 首页和排期页均支持下拉刷新，触发时清除本地缓存并重新从云端同步状态，确保本地缓存与数据库一致。

### 8.7 权限模型

```text
普通用户 (role: 'user')
  → 提交内容、查看排期、查看关于页

管理员 (role: 'admin')
  → 以上全部 + 列表审核 + 验证码管理
  → 首页显示管理后台入口

超级管理员 (role: 'superadmin')
  → 以上全部 + 测试控制台 + 管理员管理
  → 通道强制开关（绕过周日 8:00-20:00 时间校验）
  → 通过特殊验证码获取身份（bcrypt 哈希校验，源码不暴露原码）
  → 可生成/删除管理员通行码，可撤销管理员身份
```

### 8.8 验证码生命周期

```text
周五 02:00 → autoGenerateWeeklyCode 自动生成3个码（直接发布）
周日 08:00 → 提交通道开放，用户输入验证码
周日 20:00 → 提交通道关闭，触发自动抽取
周日 24:00 → 验证码过期（expire_date = 周一日期）
```

管理员也可通过后台手动添加、编辑（草稿状态）、发布、删除验证码。

### 8.9 安全模型

**数据库安全规则：** 每个集合配置独立的读写权限；带文档字段限制的规则要求客户端查询条件包含相同字段：

```text
users           → 禁止客户端一切操作
submissions     → 仅可读取 user_id 等于当前微信用户的记录，禁止客户端写
schedules       → 仅可读取 status == published 的记录，禁止客户端写
weekly_codes    → 禁止客户端一切操作
message_subscriptions → 仅可读取、创建 openid 等于当前微信用户的记录，禁止客户端更新和删除
admin_passcodes → 禁止客户端一切操作
login_attempts  → 禁止客户端一切操作
configs         → 禁止客户端一切操作（仅云函数可读写）
schedule_exceptions → 禁止客户端一切操作
submission_counters → 所有人可读，禁止客户端写
```

`submissions` 的客户端查询会把 `getUserInfo` 云函数返回的当前用户 `openid` 放入 `user_id` 条件；数据库安全规则再用 `auth.openid` 独立校验，两者不一致时查询会被拒绝：

```js
db.collection('submissions')
  .where({ user_id: userInfo.openid, week_key: currentWeekKey })
```

**云函数不受安全规则限制：** 云函数始终拥有完整数据库访问权限，安全规则仅约束客户端直接调用。

**唯一索引：** `submissions` 集合建立 `(user_id + week_key)` 唯一索引，配合事务中的 duplicate key 检测，从数据库层面杜绝并发重复提交。

### 8.10 订阅消息通知

**通知类型：**

| 模板          | 触发场景  | 接收者    | 跳转页面                   |
| ----------- | ----- | ------ | ---------------------- |
| 参与活动提醒（管理员） | 抽取完成后 | 已订阅管理员 | `pages/admin/admin`    |
| 新活动发布提醒（用户） | 排期发布后 | 已订阅用户  | `pages/playlist/index` |

**订阅流程（管理员/学生统一）：**

```text
用户进入页面 → 检查本周是否有未消费的订阅记录
  → 有：显示绿色"已开启"卡片
  → 无：显示橙色"点击开启"按钮
→ 点击按钮 → 弹出微信授权框 → 用户点"允许"
→ 创建 message_subscriptions 记录（consumed: false）
→ 卡片变绿
→ 触发事件（抽取/发布） → 云函数查找未消费记录 → 发送通知 → 标记 consumed
→ 下次进入页面 → 记录已 consumed → 按钮变回灰色 → 需手动再点一次
```

**发送去重：** 云函数 `notifyAdmins()` / `notifyStudents()` 使用 Set 按 openid 去重，同一用户多条记录只发一次通知，多余记录标记 consumed。

**管理员身份校验：** `notifyAdmins()` 发送前查询 `users` 集合，确认用户仍是 admin/superadmin，被撤销的管理员不再收到通知。

### 8.11 超管通道开关（三态）

超管可通过测试控制台控制提交通道，支持三种模式：

- **强制开放**：绕过周日 8:00-20:00 时间校验，随时允许提交（用于审核人员测试）
- **强制关闭（假期模式）**：完全锁定通道，即使周日也不允许提交（假期学生不在校时使用）
- **恢复正常**：回到默认的周日 8:00-20:00 时间校验

**优先级链：** `forceClose(true)` → 拒绝 → `forceOpen(true)` → 开放 → 时间校验

**数据存储：** `configs` 集合 `_id: "channel_override"` 文档，字段 `forceOpen: true/false` 和 `forceClose: true/false`。

**完整链路：**

```text
测试台 UI → admin.js onToggleChannel(mode)
  → testTool toggleChannel → 写入 configs.channel_override（同时更新 forceOpen 和 forceClose）
  → 返回首页 → onShow → getUserInfo 云函数 → 读取 configs → 返回 channelForceOpen + channelForceClose
  → index.js checkTimeAndSubmission() → 优先判断 channelForceClose → 再判断 channelForceOpen → canSubmit
```

**云函数端拦截：** `checkWeeklyCode` 在时间校验前先读取 `configs`，`forceClose` 为 true 时直接拒绝提交并返回"假期模式"提示。

**安全设计：** 通道状态由 `getUserInfo` 云函数在服务端读取（不受前端安全规则限制），前端仅消费 `userInfo.channelForceOpen/channelForceClose` 字段，不直接访问 `configs` 集合。

## 九、关键技术细节

### 9.1 数据库分页

`.get()` 在云函数中最多返回 100 条，超过需分页循环：

```js
let all = [];
let skip = 0;
while (true) {
  const batch = await db.collection('xxx').where({...}).skip(skip).limit(100).get();
  all = all.concat(batch.data);
  if (batch.data.length < 100) break;
  skip += 100;
}
```

### 9.2 批量删除

`.remove()` 单次最多删除 100 条，需循环：

```js
async function removeAll(collection, where) {
  while (true) {
    const res = await db.collection(collection).where(where).limit(100).get();
    if (res.data.length === 0) break;
    const ids = res.data.map(d => d._id);
    await db.collection(collection).where({ _id: _.in(ids) }).remove();
  }
}
```

### 9.3 原子递增

使用 `_.inc()` 命令实现并发安全的计数递增：

```js
await db.collection('submission_counters').doc(weekKey).update({
  data: { count: _.inc(1) }
});
```

### 9.4 事务

提交内容、抽取写入、排期发布都使用数据库事务，确保一致性：

```js
const transaction = await db.startTransaction();
// ... 多步操作 ...
await transaction.commit();
// 出错时：await transaction.rollback();
```

### 9.5 bcrypt 密码安全

管理员通行码使用 `bcryptjs` 库进行哈希存储，源码和数据库中均不保存明文：

```js
const bcrypt = require('bcryptjs');
const hash = await bcrypt.hash(plainCode, 10);  // 生成哈希（cost=10）
const match = await bcrypt.compare(input, hash); // 验证时比对
```

超管哈希通过 `verifyAdmin` 云函数的 `SUPER_ADMIN_HASH` 环境变量注入，不进入源码和 Git 历史；环境变量缺失时函数会安全拒绝管理员验证。普通管理员通行码的哈希存储在 `admin_passcodes` 集合，仅保留脱敏预览（如 `AB****`）。

### 9.6 错误信息脱敏

云函数返回给前端的错误信息不包含 `err.message`，避免泄露内部实现细节：

```js
// ❌ 不推荐
return { success: false, message: err.message };

// ✅ 推荐
return { success: false, message: '系统繁忙，请稍后重试' };
```

日志中使用 `console.warn` 而非 `console.error`，仅记录 `err.message` 不记录完整错误对象。

### 2026-05-31 — 管理员通行码暴力破解防护（测试版 ✅ | 发布版 ✅）

**防止恶意脚本穷举管理员通行码（6位码理论上有 36^6 种组合）。**

**防护机制：**

- `cloudfunctions/verifyAdmin/index.js` — 新增 per-openid 频率限制

  - **失败计数**：每次验证失败递增 `login_attempts` 集合中的 `fail_count`

  - **锁定机制**：连续失败 5 次后锁定该用户 15 分钟

  - **自动解锁**：锁定时间到期后自动解锁，失败计数归零

  - **成功清除**：验证成功后立即清除所有失败记录

  - **用户提示**：

    - 失败时显示"通行码错误，还剩 X 次尝试机会"

    - 锁定时显示"尝试次数过多，已锁定 15 分钟"

**新增集合：** `login_attempts`

| 字段             | 类型        | 说明        |
| -------------- | --------- | --------- |
| `_id`          | string    | 用户 openid |
| `fail_count`   | number    | 连续失败次数    |
| `locked_until` | Date/null | 锁定截止时间    |
| `last_attempt` | Date      | 最后尝试时间    |

**配置参数（代码顶部常量）：**

| 参数                 | 值    | 说明       |
| ------------------ | ---- | -------- |
| `MAX_FAIL_COUNT`   | 5    | 最大连续失败次数 |
| `LOCK_DURATION_MS` | 15分钟 | 锁定时长（毫秒） |

**安全性提升：**

- 即使攻击者知道 openid（理论上不可知），也无法暴力破解通行码

- 5 次 / 15 分钟 = 每天最多尝试 480 次，远低于 22 亿种组合
