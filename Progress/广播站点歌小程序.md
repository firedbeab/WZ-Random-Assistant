#### 2.3 实施后的投稿状态模型

| 状态 | 含义 | 参与抽取 | 可作为历史候补 | 删除策略 |
| --- | --- | --- | --- | --- |
| `pending` | 本周正常候选 | 是 | 不适用 | 抽取或发布时转状态 |
| `selected` | 已进入待审核/已发布排期 | 否 | 否 | 随过期数据清理 |
| `carryover` | 有效但未抽中 | 仅作为后备 | 是 | 最多保留两周 |
| `rejected` | 管理员明确移除或跳过 | 否 | 否 | 随过期数据清理 |
| `overflow` | 超过 250 条后的无感知提交 | 否 | 否 | 发布后删除，过期清理兜底 |
| `removed` | 超管从提交管理中移除 | 否 | 否 | 保留恢复期后清理；不参与有效计数和同名判重 |

## 三、当前核心业务规则

> 本节描述 2026-10-05 已部署云端代码；前端控制台和展示增强仍需随下一版小程序代码上传。

### 3.1 每周流程

```text
周五 02:00       自动生成并发布本周验证码
周日 08:00       提交通道开放
周日 08:00-20:00 用户提交内容
周日 20:00       自动抽取，生成待审核排期
管理员审核        标记异常、自动替补、跳过日期、编辑备注
管理员发布        排期变为 published，向已订阅用户发送通知
周一至周五        用户查看本周排期
```

所有业务日期按北京时间 UTC+8 计算。`week_key` 使用相关周日的 `YYYY-MM-DD`。

### 3.2 通道状态

默认开放条件：周日 8:00-20:00。

| 模式 | `forceOpen` | `forceClose` | 结果 |
| --- | --- | --- | --- |
| 正常 | false | false | 按时间窗口判断 |
| 强制开放 | true | false | 跳过时间限制 |
| 强制关闭 | false | true | 始终拒绝提交 |

优先级：强制关闭 > 强制开放 > 默认时间窗口。前端只负责展示，`checkWeeklyCode` 会在服务端再次校验。

### 3.3 当前提交链路

```text
参数类型与长度校验
→ 服务端时间窗口和通道状态校验
→ 微信文本内容安全检测
→ 开启数据库事务
→ 验证已发布验证码及到期日期
→ 检查 user_id + week_key，限制每人每周一次
→ 按规范化 song_key 检查本周同名内容
→ 统计本周 pending 数量
→ 未满250条：完整写入 pending
→ 已满250条：完整写入 overflow，仍返回成功并增加计数
```

`overflow` 保存内容名称、歌手和特殊备注，使用户刷新或更换设备后仍能看到自己的提交；它不参与抽取或异常替补，并在本周排期成功发布后清理。

### 3.4 当前名称判重规则

`song_key` 由内容名称计算：

- 使用 Unicode NFKC 统一全角和半角。
- 英文统一为小写。
- 忽略空白、标点和符号。
- 歌手、补充说明和特殊备注不参与唯一性判断。
- 旧数据没有 `song_key` 时按 `song_name` 即时计算。

| 输入 A | 输入 B | 当前判定 |
| --- | --- | --- |
| `夜曲` | `夜 曲` | 相同 |
| `Hello!` | `ＨＥＬＬＯ` | 相同 |
| `《夜曲》` | `🎵夜曲` | 相同 |
| `晴天` | `晴天（Live版）` | 不同 |

边界：错别字、别名、拼音或额外文字仍可能绕过；过度模糊匹配会误伤真正不同内容，当前不启用。

### 3.5 当前抽取规则

1. 分页读取本周所有 `pending`，以及前两周所有 `carryover`。
2. 当前用户本周已有任意提交时，不再使用该用户的历史候补，避免同一用户一周占两个位置。
3. 按规范化 `song_key` 去重；同名多人提交时随机保留一条，避免始终偏向早提交者。
4. 从前两周已发布 `schedules` 建立重复集合。
5. 候选优先级为：本周新内容 → 历史新内容 → 本周重复内容 → 历史重复内容。
6. 依次填入 `day1` 至 `day5`，每天最多 4 项，共 20 项；所有候选不足时保留空位。
7. 事务写入一条 `revision=1` 的待审核排期，并把被选提交改为 `selected`；排期项目保留 `source_week_key`。

### 3.6 审核与发布

- `markException`：移除单项、记录异常、原提交改为 `rejected`；优先从本周 `pending` 替补，不足时使用前两周 `carryover`。
- `skipDay`：清空指定日期，相关提交改为 `rejected`，写入异常记录。
- `updateNote`：更新或删除特殊备注；空备注在最终列表不渲染节点。
- `publish`：事务内把排期从 `pending` 改为 `published`；随后把本周剩余 `pending` 改为 `carryover`、清理当周 `overflow` 并发送用户通知。
- 清理和通知互相隔离；任一失败不撤销已经成功的发布。

### 3.7 当前数据保留

每次 `drawWeeklyPlaylist` 运行前保留当前周、前一周和前两周。更早的 `schedules` 和 `submissions` 会被批量删除；已消费且超过两周的订阅记录也会清理。

### 3.8 本地缓存

| 缓存 | 用途 | 当前刷新策略 |
| --- | --- | --- |
| `prod_last_submission` / `test_last_submission` | 当前设备快速显示本周提交曲目 | 按运行环境隔离；进入和下拉刷新会用云端本人投稿校准，`overflow` 不因刷新丢失 |
| `prod_schedule_cache_{week_key}` / `test_schedule_cache_{week_key}` | 已发布列表 | 按运行环境隔离；所有缓存命中均先渲染，再后台静默校验云端，撤回后会清除旧缓存 |
| 使用说明缓存 | 网络异常时显示最近成功内容 | 下拉刷新强制请求 |
| 说明大图缓存 | 避免重复下载大图 | 约 12MB，按最久未查看淘汰 |
| `admin_auth` | 旧版兼容标记 | 实际角色始终由云端 `users.role` 决定 |

### 4.4 权限角色

### 4.5 正式与测试数据域

| 项目 | 开发版 / 体验版 | 正式发布版 |
| --- | --- | --- |
| 识别依据 | `envVersion !== 'release'` | `envVersion === 'release'` |
| 数据集合 | `test_users`、`test_submissions` 等 `test_` 集合 | `users`、`submissions` 等原集合 |
| 云存储说明图片 | `test/help/` | `help/` |
| 本地缓存 | `test_` 前缀 | `prod_` 前缀 |
| 页面提示 | 显示测试模式横幅 | 不显示 |
| 微信订阅 | 只模拟按钮状态，不申请、不写记录、不发送 | 正常申请、保存和发送 |
| 定时任务 | 无独立触发器；需要时在测试台手动触发 | 原有周五验证码、周日抽取触发器 |

客户端通过 `utils/runtime.js` 给云函数调用统一附加 `_testMode`。服务端不只相信该参数：请求测试数据时还会到正式 `users` 集合确认调用者是 `superadmin`。没有 `_testMode` 的调用默认生产数据域，因此线上定时触发器和正式旧调用不会被自动切到测试数据。

这是同一 CloudBase 环境内的逻辑隔离：数据、缓存和业务副作用隔离，但云函数代码、实例、日志、套餐资源点和存储桶仍共享。云函数部署和运行时升级仍应视为生产变更。

## 八、安全、隐私与性能

### 8.1 管理员安全

- `users.role` 是唯一可信身份来源；本地缓存不能授予权限。
- 超级管理员 bcrypt 哈希只存在 `verifyAdmin` 云函数环境变量 `SUPER_ADMIN_HASH`，不进入源码和 Git 历史。
- 普通管理员通行码使用 bcrypt 哈希，明文仅在创建时返回一次。
- 登录连续失败 5 次锁定 15 分钟。
- 管理云函数校验角色、输入类型、长度、文档 ID 和索引范围。
- 返回客户端的错误信息脱敏；详细异常只写云函数日志。

### 8.2 投稿安全

- 时间窗口、验证码、每周次数和通道状态均由服务端校验。
- 标题、补充说明和特殊备注有服务端类型与长度限制。
- 普通提交调用微信文本内容安全接口；明确违规会拒绝。
- `(user_id, week_key)` 唯一索引作为并发兜底。
- 2026-10-04 起歌手不参与内容唯一性，防止修改歌手绕过。

### 8.3 隐私

- 不主动获取微信昵称、头像、手机号或通讯录。
- 使用 openid 识别用户和管理员，但前端只在业务必要范围内使用。
- 测试审计不返回具体 openid。
- 使用说明图片只读取超级管理员主动选择的照片，不读取未选择内容。
- 公众平台隐私指引已声明“选中的照片或视频信息”及文本/图片 UGC 场景。
- 仓库不包含用户数据、管理员明文通行码、超管哈希、私钥或真实本地项目配置。

### 8.4 内容安全

- 普通用户提交：`msgSecCheck` 检查标题、歌手/补充说明和特殊备注。
- 管理员备注：保存非空内容前执行 `msgSecCheck`。
- 使用说明：草稿可保存；发布标题、摘要和正文必须通过 `msgSecCheck`。
- 使用说明图片：超管入口、数量/大小限制、文件签名验证和管理员人工把关；当前未增加异步图片内容审核。

### 8.5 性能现状

- 首页用户信息与通道配置并行读取；提交状态和计数并行加载。
- 管理后台按页签加载，避免首屏请求全部管理数据。
- 抽取分页读取候选，候选和历史排期并行读取。
- 清理使用 `Promise.allSettled`，单项失败不阻断主流程。
- 已发布列表和使用说明使用本地缓存；大图采用按需下载和本地淘汰缓存。
- 已启用按需注入；当前页面声明的 `privacy-popup` 均实际使用。
- We分析中的同步 Storage 建议只有约 2-3ms 收益，属于低优先级，不为此单独发布。

## 九、部署与运维

### 9.1 环境规则

- 小程序仍连接同一个 CloudBase 环境，但运行时自动选择逻辑数据域：开发版/体验版走 `test_`，正式发布版走原集合。
- 环境判断只依赖微信提供的 `envVersion`：无法读取时按测试模式处理，采用“失败时不写正式数据”的保守策略。
- 不提供可由页面或本地缓存切换到生产数据的调试开关；测试数据访问还需要服务端确认正式超管身份。
- 正式定时任务、没有 `_testMode` 的调用和正式发布版继续使用生产数据域。
- 测试模式横幅只在开发版/体验版显示；看到横幅说明当前页面正在使用测试数据域，不是正式版被改成了测试模式。
- 前端代码和云函数是两套部署：上传小程序不会自动部署云函数。
- 只改云函数时，部署对应云函数即可；只改前端时，上传小程序代码即可。

当前不是物理独立环境。云函数代码、云环境套餐用量、日志和存储桶仍共享，因此部署云函数、调整运行时、修改触发器或耗用大量资源仍可能影响生产；普通投稿、排期、验证码、用户、计数、说明内容和测试清理已经按数据域隔离。

### 9.2 云函数部署

可通过微信开发者工具右键云函数上传部署，或使用开发者工具 CLI 增量部署 `index.js`。部署后必须查询函数状态，只有 `Active` 才算完成；`Updating` 只是仍在发布中。

修改依赖或配置时不能只增量上传 `index.js`，应使用完整部署并确认依赖、环境变量、超时和定时触发器。

### 9.3 前端上传

- 页面底部版本文字不会自动设置平台版本号。
- 上传时在微信开发者工具填写实际版本号和更新说明。
- 提审版本隐私指引与现网隐私指引是两套入口；开发版本调用的隐私接口发生变化时，要在提交审核页面再次核对。

### 9.4 GitHub

- 公开仓库只保留 `project.config.example.json`。
- `.gitignore` 排除 `node_modules`、`.cloudbase`、真实项目配置、密钥、证书和本地助手状态。
- 推送前扫描明文密码、bcrypt 哈希、AppID、Token、SecretId 和私钥块。
- 当前没有开源许可证：代码可公开查看，但未额外授予复用许可。

### 9.5 清理与恢复

- 自动抽取保留当前周和前两周排期/投稿。
- 清理失败只记录警告，不阻止当周抽取。
- 发布后的剩余 `pending` 转为 `carryover`；当周 `overflow` 在发布后批量删除，失败时由过期清理兜底。
- 正式环境 `clearAll` 永久禁用。
- 尚未形成完整数据库备份与恢复手册，属于 P0 待办。

## 十二、重要历史决策

### 12.1 250 条无感知上限

最初目的：控制实际抽取池规模，同时不在高峰期向普通用户展示“名额已满”。当前代码在达到 250 条后返回成功并增加计数，但不保存内容。

2026-10-04 讨论确认：保留无感知体验，但计划把超额提交保存为 `overflow`，使用户刷新和换设备后仍能看到曲目，并利用唯一索引阻止重复计数。`overflow` 永不参与抽取，发布后删除。

### 12.2 历史重复不是绝对禁止

当前算法优先使用近两周未出现的内容；如果本周新内容不足，会使用近两周出现过的本周投稿补位。这样避免因为候选不足产生过多空位。

计划加入历史候补后仍遵守“新内容优先”，但历史未抽中且未播放内容会排在本周重复内容之前。

### 12.3 管理员身份必须在云端恢复

本地 `admin_auth` 不能作为权限依据。换设备后由 `getUserInfo` 根据 openid 返回 `users.role`，页面据此直接进入后台；所有管理云函数再次独立校验角色。

### 12.4 超管密码保持不变但源码不保存哈希

超管只有项目负责人本人。现有密码不因公开仓库而强制更换，但 bcrypt 哈希已经迁移到云函数环境变量，公开源码和 Git 历史中不包含哈希。

### 12.5 测试采用同云空间逻辑隔离

2026-10-04 根据项目体量和套餐资源决定暂不新建第二个 CloudBase 环境。开发版/体验版自动访问 `test_` 集合，正式发布版和定时任务默认访问生产集合；服务端还会验证正式超管身份。该方案足以隔离日常投稿、抽取、审核、发布、说明和清理测试，但不隔离云函数代码、运行时、配额、日志和存储桶，因此不能代替灾备环境。需要测试运行时升级、函数版本隔离或高负载时，再建立物理独立环境。

### 12.6 图片采用客户端直传、服务端复核

Base64 放入 `cloud.callFunction` 会触发参数大小限制。当前由超管客户端直传随机云存储路径，再由云函数验证身份、文件归属、大小和文件头后才允许写入说明。普通用户没有管理入口。

### 12.7 超管删除采用可恢复移除

2026-10-04 确认：超管在投稿详情中执行批量“删除”时，服务端不直接物理删除记录，而是转为 `removed`，同步调整计数并写入操作原因和审计。这样可以阻止该记录进入抽取和候补，同时保留误操作恢复及追查恶意提交的依据。`removed` 不参与内容同名判重，但用户周唯一约束继续生效。

### 12.8 不为控制台低收益建议单独发布

We分析报告曾提示首页重复读取 Storage 约 3ms、列表首屏同步读取约 2ms，以及历史版本声明未使用 `channel-video`。当前代码已无 `channel-video`，并已开启按需注入；同步缓存读取换来了更快的本地内容显示。除非真实用户数据证明存在明显启动问题，否则不为了消除数毫秒提示增加发布风险。

- 新更新日志按倒序插入，不再追加到文档最底部。
